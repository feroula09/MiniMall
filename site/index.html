從逛商品到確認收貨，一間完整的小商店

Mini Mall 是用 Next.js 做的微型電商練習專案。顧客可以瀏覽商品、加入購物車、下單並模擬付款；管理員在後台管理商品、分類和訂單。

顧客和管理員各自能做的事

兩種角色共用同一個網站。登入後依帳號角色決定能不能進後台，權限在伺服器上逐一檢查。

顧客

  • 用關鍵字、分類、價格排序找商品，結果可分頁
  • 註冊、登入、登出
  • 加入購物車、調整數量，不會超過庫存
  • 填寫收件資料下單，再模擬付款
  • 查看訂單、取消未出貨的訂單、確認收貨

管理員

  • 概覽頁看商品數、訂單數、待出貨數和已付款金額
  • 新增、修改、刪除分類；還有商品的分類不能刪
  • 新增、修改、上下架商品，並上傳商品圖片
  • 依狀態篩選訂單，處理出貨或取消

一張訂單會經過的狀態

每次狀態變更都只能照下面的順序走。兩個人同時操作同一張訂單時，後送出的那個會收到衝突提示，不會互相覆蓋。

  1. 待付款顧客下單

    庫存在下單當下就先扣掉

  2. 已付款顧客付款

    模擬付款，不會真的扣款

  3. 已出貨管理員出貨

    出貨後就不能再取消

  4. 已完成顧客確認收貨

    訂單結束

已取消：待付款和已付款的訂單可以取消，顧客和管理員都能操作。取消後扣掉的庫存會加回去。

容易出錯的地方怎麼處理

電商的錯誤多半出在金額和庫存。這幾個地方都有對應的寫法和單元測試。

金額不會有小數誤差
所有金額都用「分」的整數儲存與計算，例如 $129.5 存成 12950，只在畫面上換成元。
不會賣出比庫存多的商品
下單在同一個資料庫交易裡完成，扣庫存時附上「庫存足夠」的條件，兩人搶最後一件只有一人成功。
舊訂單不受商品改價影響
下單時把商品名稱、圖片和單價存進訂單明細，之後商品改價或刪除，歷史訂單照樣正確。
不能靠改網址操作別人的資料
每個寫入動作都在伺服器上依序檢查：是否登入、角色、輸入格式，以及這筆資料是不是你的。

在自己電腦上執行

網站需要伺服器和資料庫，無法直接放在這個頁面上執行。最快的方式是用 Docker 啟動，打開 http://localhost:3000 就能使用。

用 Docker

docker run -d -p 3000:3000 \
  -v minimall-data:/app/data \
  -v minimall-uploads:/app/storage \
  ghcr.io/feroula09/minimall:latest

用 Node.js 24

git clone https://github.com/feroula09/MiniMall.git
cd MiniMall
npm install
cp .env.example .env    # 填入 SESSION_SECRET
npx prisma migrate dev
npx prisma db seed
npm run dev

測試帳號

  • 管理員admin@minimall.dev
    admin1234
  • 一般顧客user@minimall.dev
    user1234

Docker 版第一次啟動會自動建立資料庫並寫入測試資料。資料存在 volume 裡，重新啟動不會消失。
